# 市场观点解析器验证方案

状态：待设计确认后执行  
适用范围：内置“市场观点与情绪提炼”解析器及其后续版本

## 1. 验证原则

- 同一批 ASR 样本同时运行正式版本和测试草稿，避免样本差异影响结论。
- 先证明观点是否正确，再评价摘要是否写得好看。
- 所有正式观点必须能够定位到原始 ASR，不接受无证据结论。
- 高风险误报比普通漏报更严重：不得把观众提问、主播转述或模型猜测包装成主播明确观点。
- 自动指标用于筛选版本，最终发布仍需要人工查看差异样本。

## 2. 金标样本

### 2.1 样本规模

首轮不少于 100 个连续语义片段，建议来自不少于 5 个直播间，覆盖开盘、盘中和复盘表达。一个片段保留前后各 30–60 秒上下文。

### 2.2 人工标注字段

```ts
interface InsightGoldLabel {
  sampleId: string
  roomId: string
  startAt: string
  endAt: string
  asrText: string
  isEffective: boolean
  nature: "explicit" | "conditional" | "quote" | "inference" | "fact" | "noise"
  subjects: Array<{
    originalName: string
    normalizedName?: string
    kind: "market" | "sector" | "indicator" | "style" | "sentiment"
  }>
  direction?: "positive" | "neutral" | "cautious" | "risk"
  conditions: string[]
  evidenceText: string[]
  alertLevel: "none" | "normal" | "important"
}
```

### 2.3 必须覆盖的反例

- 寒暄、点赞和关注引导；
- 商品或课程广告；
- 观众提出的问题；
- 主播没有表示认可的第三方转述；
- 只有“热闹、很强、有人气”等描述但没有市场方向；
- 否定句、反问句和随后被纠正的口误；
- 同一观点的重复表达；
- 使用“高位方向、AI 那边、抱团”等非标准名称的表达。

## 3. 离线评测指标

| 指标 | 计算方法 | 发布门槛 |
| --- | --- | --- |
| 重点观点精确率 | 正确的重点观点 / 模型输出的全部重点观点 | `>= 90%` |
| 有效观点精确率 | 正确有效观点 / 模型输出的全部有效观点 | `>= 85%` |
| 有效观点召回率 | 被识别的金标有效观点 / 全部金标有效观点 | `>= 75%` |
| 观点性质准确率 | explicit、conditional、quote、inference、fact 分类正确率 | `>= 85%` |
| 证据一致率 | 证据原文确实支持结论的结果占比 | `>= 95%` |
| 时间定位成功率 | 能定位到有效 ASR 自然时间的结果占比 | `100%` |
| 结构完整率 | 必填字段齐全且通过 Schema 校验的结果占比 | `>= 99%` |

测试草稿发布还必须满足：

1. 高风险误报数量不得高于正式版本。
2. 重点观点召回率不得比正式版本下降超过 5 个百分点。
3. 所有历史回归反例必须继续通过。
4. 模型输出无法通过 Schema 校验时不得进入正式观点库。

## 4. 实时灰度

设计确认后，测试草稿可以旁路运行 10–20 分钟：

- 接收与正式版本相同的 ASR 片段；
- 结果写入测试结果表，不进入用户正式观点流；
- 不触发系统警示；
- 不改变直播间当前主解析器；
- 测试结束后展示延迟、调用量、失败率、观点数量和人工认可率。

实时门槛：

- 从 ASR final 到观点产生的 P95 延迟不超过 15 秒；
- 模型调用失败率低于 2%；
- 同一个语义观点重复输出率低于 5%；
- 单路解析失败不影响 ASR 和其他直播间；
- 停止灰度后不存在残留请求、定时器或任务队列。

## 5. 自动化测试

### 5.1 单元测试

- 解析器配置、版本和状态 Schema 校验。
- 正式版本不可原位修改；编辑必须产生测试草稿。
- 一个直播间最多绑定一个正式解析器。
- 观点结果必须包含 roomId、parserVersion、自然时间和证据引用。
- 相同观点去重、Schema 失败拒绝入库、低置信度降级。

### 5.2 集成测试

- 固定 ASR fixture 同时进入正式和测试解析器，结果按运行 ID 隔离。
- 测试结果不会进入正式观点查询，也不会触发警示。
- 发布草稿后新 ASR 使用新版本，历史结果仍保留原版本号。
- 删除或停用解析器不会删除历史观点证据。
- 模型超时、限流、无效 JSON 和中途断线能够重试或失败收敛。

### 5.3 Electron E2E

1. 新建解析器并保存草稿。
2. 选择历史 ASR 样本运行对照测试。
3. 人工标记一个误报和一个正确结果。
4. 发布新版本并绑定一个直播间。
5. 注入 fixture ASR，验证观点卡片和证据时间。
6. 切换到“不使用解析器”，验证 ASR 继续但不再产生新观点。
7. 重启应用，验证解析器、绑定关系、版本和观点历史完整恢复。

## 6. 人工阅读验收

由至少一名熟悉市场表达的用户完成：

- 5 秒内判断当前市场情绪和重点板块；
- 10 秒内找到某条观点的原始 ASR 证据；
- 能区分明确观点、条件观点和系统推断；
- 能识别测试草稿相对正式版本消除了哪些误报；
- 不阅读帮助文档也能完成“编辑草稿 → 测试 → 发布”；
- 不会误以为保存草稿已经影响正在运行的直播间。

## 7. 验收证据

- 固定金标数据集及标注版本号；
- 正式版与测试版逐条对照报告；
- 自动测试日志和 E2E 截图；
- 实时灰度延迟与失败率报告；
- 发布版本、模型、提示配置和评测数据集的关联记录。
