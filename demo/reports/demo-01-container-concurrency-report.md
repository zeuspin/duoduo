# Demo 01：独立浏览器容器并发播放验证报告

## 1. 验证目标

确认同一台 macOS 测试电脑能否匿名并行播放 3 个公开抖音直播间，且直播之间互不停止。该 Demo 是 P0 前置验证；若无法稳定隔离并发直播，不应进入独立音频、ASR 和多直播聚合开发。

## 4. 测试方案

### 4.1 方案 A：3 个 Chrome Profile

目标：验证同一 Chrome 安装下，不同 Profile 是否能并行维持 3 路匿名直播。

步骤：

1. 创建或使用 3 个彼此隔离的 Chrome Profile。
2. 每个 Profile 打开 1 个直播 URL。
3. 确认不登录抖音账号，不输入账号、密码、验证码或 Cookie。
4. 同时播放 3 路直播，连续观察 2 小时。
5. 记录停流、重载、登录弹窗、页面异常、任一路刷新或关闭是否影响其他路。

验收：

- 3 路均持续播放 2 小时。
- 任一路刷新、关闭或异常退出不影响其他路。
- 无账号登录要求；如出现登录要求，标记该直播间不支持，而不是登录。

### 4.2 方案 B：3 个独立 Chrome 进程 + 独立 user-data-dir

目标：验证完全独立用户数据目录是否比 Profile 更稳定。

步骤：

1. 为 3 路直播分别准备独立 `user-data-dir`。
2. 使用 Chrome 启动 3 个独立实例。
3. 每个实例打开 1 个直播 URL。
4. 连续观察 2 小时。
5. 记录进程、播放状态、登录弹窗、停流、重载和互相影响情况。

验收：

- 3 路均持续播放 2 小时。
- 关闭或刷新任一进程不影响其他进程。
- 直播状态和异常可单独归因到对应进程。

### 4.3 方案 C：Chrome + Safari 对照组

原计划为 Chrome / Safari / Firefox 对照组。当前 Firefox 未安装，因此本轮先执行 Chrome + Safari 对照；如需要完整三浏览器对照，应先安装 Firefox 后补测。

步骤：

1. Chrome 打开 1 到 2 路直播。
2. Safari 打开 1 路直播。
3. 连续观察 2 小时。
4. 记录跨浏览器是否更稳定，以及是否出现匿名访问限制。

验收：

- 至少 3 路直播总计持续播放 2 小时。
- 任一浏览器关闭、刷新或异常不影响另一浏览器。
- 若 Chrome 多 Profile 不稳定，但 Chrome + Safari 稳定，可作为短期降级方案。

Go 条件：

- 至少一种方案满足 3 路公开匿名直播连续播放 2 小时。

No-Go 或降级：

- 若没有方案达标，暂停多直播产品，降级为单直播工具验证。
- 若 Chrome 多 Profile 不稳定但独立进程稳定，采用独立进程方案。
- 若同品牌浏览器仍受限制，短期采用 Chrome + Safari 等多浏览器内核对照方案。
- 若直播 URL 要求登录，标记该直播间不支持，换用备用公开直播 URL。
