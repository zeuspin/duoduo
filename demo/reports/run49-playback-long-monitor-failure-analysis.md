# run49 三路播放长稳失败分析

## 结论

Task 1.1 的 2 小时三路匿名播放长稳未通过，当前结论为 No-Go。

run49 在长监控前通过 run48 门禁，初始 3 路均可匿名播放；正式监控也完成了 12/12 个 checkpoint。但 `all_checkpoints_three_ok=false`，不能作为“3 路连续播放 2 小时”验收通过证据。

## 归因

这次失败不支持“独立匿名容器不能并行播放”的结论，因为启动阶段和早期 checkpoint 已证明三路可并行播放；run45/run46/run47 也证明短时播放、关闭一路、刷新一路的 smoke 可行。

更符合证据的失败原因是：当前长稳策略对直播源失效、音轨消失、页面目标退出不具备自愈能力。C1/C3 先出现音轨消失，后段三路都无法通过 CDP 找到 `live.douyin.com` 页面目标，因此监控链路没有完成“自动替换直播源 / 重建页面 / 恢复路由”的闭环。

## No-Go 边界

在没有补齐以下能力并重新通过 2 小时长稳前，Task 1.1 不能进入 Pass：

- 某一路 `video-not-ready-or-no-audio-track` 连续出现时，自动判定为直播源失效并换到备用候选。
- 某一路找不到 `live.douyin.com` 页面调试目标时，自动重建该路无登录 Chrome profile / 页面。
- 某一路自愈时，不重启或污染其他路由。
- 长稳报告必须记录每次自愈动作、原房间、替换房间、恢复用时和是否影响其他路。

## 下一步策略

1. 将 `run_adaptive_three_live_capture.py` 已验证过的候选门禁和换源策略迁移到播放长稳监控。
2. 为 `monitor_three_live_playback.py` 增加三类恢复动作：刷新页面、重开当前房间、换备用房间。
3. 增加恢复次数上限，避免无限重试和多开窗口。
4. 重跑 10 分钟自愈 smoke；通过后再重跑 2 小时三路长稳。
