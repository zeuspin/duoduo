# 手动直播检测与验证码保护设计

## 目标

降低匿名访问抖音直播间的频率，并在平台返回验证码中间页时立即停止继续检测，防止无效页面覆盖已保存的直播间资料。

## 检测行为

- 软件启动后对已保存直播间执行一轮检测。
- 一轮检测始终使用单任务队列，同一时间只打开一个直播间。
- 未开播直播间在启动检测结束后不再自动周期检测。
- 用户可手动检测单个直播间；一次点击后，该直播间的检测按钮进入 60 秒冷却。
- 冷却期间按钮不可点击并显示剩余秒数。
- 已处于检测队列或正在检测的直播间不得重复入队。
- 检测超时、网络错误和页面错误均不自动重试。

## 验证码中间页

- 页面出现“请完成下列验证后继续”“验证码”“安全验证”等明确证据时，识别为 `verification_required`，不得归类为普通页面错误或未开播。
- 检测到验证码后立即终止尚未开始的启动检测队列；当前房间不自动重试。
- UI 显示“需要验证”，并提示用户稍后手动检测。
- 验证码结果只更新状态、检测时间和错误原因。
- 不得使用验证码页面的标题、主播名称、封面、头像、观看人数或截图覆盖上一次成功资料。

## 数据更新规则

- 只有识别为正常直播页面并取得可信字段时，才能更新名称、主播、封面、头像和统计数据。
- `verification_required`、`timeout`、`page_error` 只写入本次状态；保留已有资料。
- `offline` 可以更新开播状态，但不使用空白页或通用页面标题覆盖已有名称。

## 验证

- 单元测试覆盖验证码识别优先级。
- 持久化测试覆盖验证码结果不覆盖已有直播间名称和封面。
- 调度测试覆盖启动队列串行执行、无周期重排、重复任务去重。
- UI 测试覆盖检测按钮 60 秒不可点击及验证码状态文案。
- 现有直播监看、播放器和 ASR 测试必须继续通过。
