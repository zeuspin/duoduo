# 多多直播 macOS 客户端产品需求

版本：V0.1  
日期：2026-07-11  
状态：首个功能实施基线

## 1. 本阶段目标

在当前 macOS 测试电脑上实现一个 Electron 桌面客户端，让用户维护公开抖音直播间，准实时识别开播状态，选择多个已开播直播间进行静默监看，并在每个直播间自己的卡片中持续看到独立实时 ASR。

## 2. 本阶段非目标

- 不筛选股票或财经直播。
- 不提炼观点、重点警示、共识或分歧。
- 不提供投资建议或自动交易。
- 不登录、不接收、不存储抖音账号、密码、Cookie 或 Safari 登录态。
- 不建设公共逐字稿库。
- 不做两小时长测；单次真实直播验收不超过 20 分钟。

## 3. 用户流程

1. 用户添加标准直播间链接并配置每周预计直播周期。
2. 系统初始化直播间，获取可用的主播名称、标题、封面或页面截图，并开始按周期检测开播状态。
3. 已开播但未监看的直播间显示在“预备直播间”卡片区。
4. 用户勾选“加入实时监看”，卡片迁移到“实时监看中”区域并展开成横向工作卡片。
5. 每个监看卡片独立展示该直播间的音频状态、ASR 状态和最新 ASR，不与其他直播间文字混排。
6. 用户点击“播放音视频”，右侧打开该直播间的 9:16 播放抽屉；同一时间最多一路声音外放。
7. 用户停止监看后，该直播间停止采音和 ASR，并返回预备直播间区域。

## 4. 核心功能

### 4.1 直播间管理

- 添加、编辑、删除直播间。
- 输入链接必须规范化为 `https://live.douyin.com/<room_id>`。
- 周期支持星期一至星期日、多时间段和停用。
- 初始化状态包括：初始化中、可用、不可匿名访问、检测异常。
- 本地持久化直播间和周期；不得持久化账号登录态。

### 4.2 开播检测

- 周期窗口外降低检测频率，周期窗口内提高检测频率。
- 状态至少包括：检测中、未开播、直播中、需要登录、页面异常、检测超时。
- 显示最近检测时间。
- 单路检测失败不得影响其他直播间。

### 4.3 实时监看

- 多个直播间可同时监看。
- 一个直播间一个独立 Electron Session partition 和 WebContents。
- 所有监看默认静音，只进行页面级独立音频采集。
- 系统观察并发数量、CPU、内存、音频连续性、ASR 延迟和错误率；本阶段不在界面显示固定负载区。

### 4.4 实时 ASR

- 每路音频独立送入百炼实时 ASR。
- ASR 事件必须携带 `room_id`、会话 ID、开始和结束时间、临时或最终状态、文本。
- 每个直播间卡片只显示本路最新 ASR。
- 临时文本和最终文本视觉区分；更新临时文本时不得产生重复最终句子。
- ASR 失败可单路重连，不中断其他直播间。

### 4.5 单路播放与回放

- 点击播放后右侧打开 9:16 WebContentsView。
- 切换播放路时，旧路立即静音但继续监看和 ASR，新路解除静音。
- 关闭抽屉只停止画面和声音外放，不停止监看。
- 本阶段回放基于客户端保留的短时音视频缓存；点击 ASR 时间定位对应片段。

## 5. 可采集直播间信息

优先获取匿名页面可稳定提供的信息：房间号、主播名称、直播标题、封面、直播状态、当前人数、点赞量。人数、点赞和热度曲线由客户端定时采样形成。任何不稳定字段允许缺失，界面隐藏缺失项，不生成假数据。

## 6. 数据与安全

- 百炼 Key 仅从根目录 `.env` 或 macOS Keychain 读取，不进入渲染进程、日志、报告和提交内容。
- 渲染进程禁止 Node integration，启用 context isolation 和 sandbox。
- 直播 WebContents 禁止任意新窗口、下载、通知、摄像头、麦克风和非必要权限。
- 音频、ASR 和短时缓存均为当前用户本地私人数据。

## 7. 本阶段验收

| 编号 | 验收标准 |
| --- | --- |
| A1 | 添加、编辑、删除后重启客户端，直播间和周期仍正确存在 |
| A2 | 至少 3 个公开直播间可并行检测，单路异常不影响其他路 |
| A3 | 至少 3 路可同时静默监看，音频与 ASR 按 room_id 独立 |
| A4 | 每个监看卡片只显示自己的 ASR，不存在全局混合 ASR 流 |
| A5 | 同时最多一路外放声音，切换播放不停止其他路 ASR |
| A6 | 真实直播测试不超过 20 分钟，结束后无残留直播进程或临时 Session |
| A7 | 自动测试、模拟端到端测试和百炼真实 smoke 全部通过 |
