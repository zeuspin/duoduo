# 多多直播股票看盘版 MVP 范围与 Go / No-Go 边界

## 1. 文档目的

本文件用于确认本次 Demo 验收和 MVP 实施的范围边界。它从原始 PRD 和执行计划中提取第一阶段目标、非目标、核心约束、验收标准和 P0 风险降级策略，作为后续 `Task 0.2`、`Task 1.1` 及之后任务的范围基线。

## 2. 当前执行前提

- 目标平台：macOS，以当前测试电脑为准。
- 当前测试电脑：macOS 26.5.1，Apple M1 Pro，16 GB 内存。
- 测试直播源：用户已提供 5 个抖音直播 URL，执行时需实时确认是否仍处于开播、公开、匿名可观看状态。
- ASR 方向：允许使用阿里云百炼相关能力，Key 已放在本地 `.env`，不得打印、复制到文档或提交。
- 测试数据权限：测试音频可临时保存，ASR 文本可用于评测，允许发送给云端 ASR / 大模型，测试期暂不考虑删除期限。

## 3. MVP 定义

多多直播股票看盘版 MVP 是一个面向个人用户的桌面信息工具。它应允许用户主动添加公开匿名可观看的抖音股票直播间，在同一台电脑上并行监听 3 路直播，分别捕获音频并实时转写，再对单直播内容进行去噪、主题事件提取和多直播主题比较。

MVP 的价值目标是提高信息获取效率、减少无效直播内容干扰、帮助用户比较不同直播间围绕同一主题的共识和分歧。MVP 不提供投资决策，不建设公共逐字稿库，不处理登录、付费、粉丝专属或私密直播。

## 4. MUST 范围

MUST 项是 MVP 成立所必需的能力。任一 P0 前置能力失败时，不应继续投入完整产品开发。

| 编号 | 能力 | 范围描述 | 可测试验收口径 |
| --- | --- | --- | --- |
| M1 | 3 路匿名直播并发 | 在当前 macOS 测试电脑上匿名打开 3 个公开抖音直播间，直播之间互不停止。 | 至少一种容器方案连续运行 2 小时；任一路刷新、关闭或异常退出不影响其他路；不输入任何抖音账号信息。 |
| M2 | 独立浏览器会话或容器 | 一个直播间对应一个隔离浏览器会话或容器，同一容器只承载一个直播。 | 3 路直播分别拥有独立 Profile、进程或等价隔离边界；容器状态可区分待启动、加载中、播放正常、无音频、需登录、已下播、异常。 |
| M3 | 独立音频捕获 | 每个直播容器形成独立音频通道，正式链路禁止整机系统混音。 | 3 路音频无串音；系统提示音、麦克风、其他应用或其他浏览器页面声音不进入任一路正式音频。 |
| M4 | 音频片段元数据 | 音频片段携带容器、直播会话、序号、起止时间和校验信息。 | 任意转写片段可定位到正确直播间、容器、音频片段和时间范围。 |
| M5 | 实时 ASR | 对每路音频形成带时间戳的实时转写，支持临时、最终、修正和撤回状态。 | ASR 临时结果 P95 <= 3 秒；最终句段 P95 <= 8 秒；完整 ASR 默认属于用户私人数据。 |
| M6 | 股票直播识别质量 | 优先保障板块名、数字、否定词、条件词、风险词和股票口语实体。 | 主题实体召回率 >= 90%；否定和风险表达召回率阶段目标 >= 97%；低置信度片段不触发高优先级摘要。 |
| M7 | 单直播信息事件 | 对单直播内容进行无效内容过滤、主题提取、方向、条件、风险和证据绑定。 | 方向识别准确率 >= 90%；条件和风险召回率 >= 95%；每个事件包含原文证据和置信度。 |
| M8 | 原意保持 | 清洗和摘要不能改变否定、条件、时间范围、风险和不确定性。 | 不得把“不要追高、等待确认、只是新闻转述”等表达改写成明确看多或交易建议。 |
| M9 | 多直播主题比较 | 对不同直播间相同或相关主题进行聚合，展示共识、分歧、新信息和风险。 | 多直播页面能区分提及数、独立观点数和重复转述数；聚合结果可回溯到直播间、时间和 ASR 证据。 |
| M10 | 虚假共识控制 | 避免把同一新闻的重复转述误判为多个独立观点。 | 主题聚类准确率 >= 85%；虚假共识率 <= 5%；少数观点保留可见。 |
| M11 | 受约束用户规则 | 用户只能配置筛选、排序、摘要密度、时间窗口、证据显示和提醒条件。 | 至少支持 3 种摘要密度和 4 种排序 / 过滤规则；越界请求被拒绝或改写为信息整理任务。 |
| M12 | 私人 ASR | 完整 ASR、完整音频和用户私人笔记默认只属于当前用户。 | 私人模式下完整 ASR 不会被其他用户访问；平台运营默认不可直接查看完整私人转写。 |
| M13 | 结构化共建 | 共建模式显式开启，仅共享结构化事件和短摘要，不共享完整 ASR、完整音频和连续原文。 | 共建默认关闭；共享字段限定为主题、方向、风险条件、发生时间、置信度等最小字段；其他用户只能看到结构化聚合。 |
| M14 | 异常监控和恢复 | 能发现无音频、无 ASR、积压、掉线、容器异常和假正常状态。 | 音频、ASR 或网络异常时自动恢复或在 60 秒内明确告警；单个容器异常不影响其他直播。 |
| M15 | 版本、纠错和回放 | ASR 修正后，下游事件、摘要和聚合支持修正、撤回、版本链和重放。 | 错误事件可撤回；新旧版本可追踪；聚合结果可重算；输出可追溯到输入和模型 / 规则版本。 |
| M16 | 基础合规边界 | 产品实际能力不得输出交易决策，也不能只依赖免责声明。 | 系统不输出买卖建议、目标价、收益概率、仓位、止损或自动交易。 |

## 5. SHOULD 范围

SHOULD 项是优先实现但不阻塞最小可行验证的能力。若资源不足，可在 MVP 内做简化。

| 编号 | 能力 | 范围描述 | 验收口径 |
| --- | --- | --- | --- |
| S1 | 5 路实验上限 | 在默认 3 路稳定后，实验 5 路并发能力。 | 5 路测试用于评估资源上限，不作为首轮 MVP 发布门槛。 |
| S2 | 资源占用概览 | 展示每路直播 CPU、内存、网络占用概览。 | 用户能看到当前资源压力；系统能根据设备能力提示建议并发数。 |
| S3 | 画质或渲染优化 | 降低不可见视频渲染开销或画质，以减少资源消耗。 | 优化不能破坏播放稳定性，不能导致音频捕获中断。 |
| S4 | 用户历史和短期复盘 | 用户查看当天处理过的直播摘要、主题时间线和观点变化。 | 历史默认私人；保存期限可配置；支持删除。 |
| S5 | 用户纠错反馈 | 用户可标记“准确、遗漏、误解”。 | 反馈进入个人纠错数据或授权质量样本，不改变公共事件事实。 |
| S6 | 共建激励展示 | 展示用户贡献了哪些结构化信息，获得了哪些额度或权益。 | 用户可理解共享范围、收益和退出方式。 |
| S7 | 投诉、纠错和删除入口 | 为用户、主播和权利人提供投诉、纠错和删除渠道。 | 发布前必须具备最小入口；灰度前可以先用人工处理流程。 |
| S8 | 热词更新 | 支持金融热词更新以改善 ASR。 | 热词只影响识别，不自动生成投资结论。 |

## 6. LATER 范围

LATER 项不进入当前 MVP。只有在核心链路稳定、隐私合规和产品边界可控后再评估。

| 编号 | 能力 | 暂缓原因 |
| --- | --- | --- |
| L1 | 支持登录、付费、粉丝专属或私密直播 | 违反当前匿名公开直播边界，涉及账号和访问授权风险。 |
| L2 | 接入专业行情、资金流、Level-2 或自动交易 | 会把产品从信息整理推向投资决策或交易系统。 |
| L3 | 买卖点、仓位、止损、目标价、收益预测 | 属于明确交易建议，不符合产品边界。 |
| L4 | 公共主播完整逐字稿库或录音档案 | 存在内容权利、隐私和替代原直播的问题。 |
| L5 | 主播排名、长期胜率或长期画像 | 容易引导为投资评价或内容监控，MVP 不做。 |
| L6 | 弹幕用户身份处理和跨直播间用户画像 | MVP 不采集弹幕身份，不做用户画像。 |
| L7 | 数十或数百直播间并发 | 当前阶段只验证 3 路默认并发，最多实验 5 路。 |
| L8 | 多平台连接器 | B 站、快手等平台放到后续扩展，不进入抖音首版验证。 |
| L9 | 团队版工作区和研究报告 | 属于后续协作产品形态，需在私人单用户闭环稳定后评估。 |
| L10 | 授权主播合作和公共摘要 | 需要单独商业和合规设计，不进入当前匿名公开直播 MVP。 |

## 7. 明确非目标

以下事项不得在当前 MVP 中实现，也不得通过用户配置绕过。

- 不要求用户登录抖音，不管理多个抖音账号。
- 不接收、不保存、不使用账号、密码、验证码、Cookie。
- 不支持必须登录、付费、粉丝专属或私密直播。
- 不提供具体股票的买入、卖出、仓位、价格、目标价、止损或收益预测。
- 不接入专业股票行情、资金流、Level-2 或自动交易。
- 不建立可公开搜索的主播完整逐字稿、录音档案或主播排名。
- 不处理弹幕用户身份，不做跨直播间用户画像。
- 不在第一阶段追求数十或数百直播间并发。
- 不把完整 ASR、完整音频、连续原文放入公共共享池。
- 不把新闻转述自动视为主播独立判断。
- 不把低置信度推测包装为确定事实。

## 8. P0 风险 Go / No-Go 降级边界

| P0 风险 | Go 条件 | No-Go 或降级边界 | 后续动作 |
| --- | --- | --- | --- |
| 独立浏览器容器是否真正并行 | 3 路匿名公开直播连续播放至少 2 小时；任一路刷新、关闭或异常退出不影响其他路；重复测试仍稳定。 | 若无法稳定隔离，暂停多直播产品；降级为单直播工具或只做容器方案专项验证。 | 不进入独立音频、ASR 和聚合开发，先重新评估独立进程、不同浏览器内核或轻量虚拟化方案。 |
| 每容器独立音频捕获 | 3 路音频无串音；不采集系统提示音、麦克风、其他应用和其他浏览器声音；连续 2 小时可用。 | 若只能录制整机混音，不进入多直播 ASR 开发。 | 改测页面级捕获、进程级音频路由或虚拟音频通道；必要时限定 macOS 或 Windows 单平台。 |
| 后台 / 最小化播放稳定性 | 最小化、切换应用不影响播放和音频；锁屏、休眠等行为有明确限制和恢复策略。 | 若后台行为不可控，MVP 必须明确“交易时段保持设备唤醒 / 不支持锁屏休眠”等使用限制。 | 增加设备唤醒提示、容器保活策略和异常恢复，不把不可保证状态宣传为支持。 |
| 股票直播 ASR 准确率 | 主题实体召回 >= 90%；否定和风险表达召回 >= 97%；最终句段 P95 <= 8 秒。 | 若风险词、否定词频繁错误，只保留原始转写或关键词，不生成观点方向和高优先级摘要。 | 增加热词、二次纠错、规则复核或云端实时 + 离线校正双层方案。 |
| 摘要不改变原意 | 方向识别 >= 90%；条件和风险召回 >= 95%；摘要无无证据股票、理由或结论。 | 若无法控制原意漂移，取消自动观点方向，只做主题、关键词和原文证据展示。 | 对高风险字段采用规则 + 模型双检；低置信度只显示原文和待确认状态。 |
| 多直播共识去重 | 主题聚类 >= 85%；独立观点识别接近 90%；虚假共识率 <= 5%；少数观点可见。 | 若虚假共识不可控，MVP 只展示“相似提及”，不宣称共识或独立观点数量。 | 增加同源转述识别、来源类型标记和人工标注回归集。 |

## 9. MVP 验收标准映射

| PRD 验收项 | 对应 MUST 项 | 验收方式 |
| --- | --- | --- |
| 同一台电脑匿名同时播放 3 个公开直播间，连续运行至少 2 小时。 | M1、M2 | `Task 1.1` 输出容器并发报告。 |
| 3 路音频互不混合，任意转写片段可定位到正确直播间和时间。 | M3、M4 | `Task 1.2` 输出音频隔离报告；后续 ASR 片段带容器和时间元数据。 |
| 关键主题词识别召回率达到可用标准，否定和风险表达召回率不低于 95%。 | M5、M6 | `Task 2.1` 输出 ASR 评估报告；本计划采用更严格的阶段目标 97%。 |
| 摘要不将谨慎、否定、新闻转述改写成明确看多。 | M7、M8 | `Task 2.2` 输出语义完整性报告和错误案例集。 |
| 多直播页面展示相同主题下的共识和分歧，并区分提及数和独立观点数。 | M9、M10 | `Task 3.1` 输出主题聚合报告。 |
| 用户可配置至少 3 种摘要密度和 4 种排序 / 过滤规则。 | M11 | `Task 3.2` 输出用户规则报告。 |
| 私人模式下完整 ASR 不会被其他用户访问。 | M12 | `Task 4.2` 输出权限矩阵测试结果。 |
| 共建模式下其他用户只能获得结构化聚合，不获得完整转写。 | M13 | `Task 4.3` 输出共建复用与权限隔离结果。 |
| 单个容器异常不会中断其他直播，异常能被发现并提示。 | M14 | `Task 4.1` 和 `Task 5.3` 输出工作台与长期稳定性报告。 |
| 系统不提供买卖建议、目标价、收益概率、仓位或自动交易。 | M16 | `Task 3.2` 和 `Task 5.4` 输出越界请求和发布前风险评审结果。 |

## 12. 下一步建议

在人工评审未完成前，可以先进入 `Task 0.2` 起草测试基线，但不建议启动真实 2 小时并发验证的正式验收计时。原因是 `Task 1.1` 的结论会直接影响是否继续多直播方向，需要先确保范围和降级口径被接受。若要完成 Task 0.1，应由对应角色在 `demo/scope-review-signoff.json` 中将 `status` 更新为 `approved`、`accepted` 或 `confirmed`，并填写 `reviewer` 与 `confirmed_at`，再运行 `demo/scripts/check_scope_signoff.py` 复算。
