# 多多直播股票看盘版 MVP 验证与实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在正式投入完整产品开发前，按可验收步骤验证“3 路匿名公开直播并行播放、独立音频捕获、实时 ASR、单直播理解、多直播聚合、隐私隔离与共建复用”是否成立，并交付一个可连续运行的 MVP 闭环。

**Architecture:** 计划采用“Demo 验证先行，MVP 实现随后”的路径。先验证容器与音频这两个最高风险输入链路，再验证 ASR 与语义保持，最后构建桌面工作台、事件数据链路、多直播聚合、受约束用户规则、隐私权限和长期稳定性。

**Tech Stack:** 当前仓库尚未包含代码；本计划不预设最终技术栈。技术选型需在阶段 0 输出候选方案后确定，候选范围包括桌面客户端、独立浏览器进程或 Profile、页面级或进程级音频捕获、云端或本地流式 ASR、服务端事件存储、前端工作台。

## Global Constraints

- 不新建分支，不推送代码，除非用户明确允许。
- 只支持无需账号登录即可公开观看的抖音直播。
- 不接收、不保存、不使用用户抖音账号、密码、验证码、Cookie。
- 一个直播间必须对应一个隔离浏览器会话或容器。
- 正式链路禁止使用整机系统混音作为主音频输入。
- 完整音频、完整 ASR、私人笔记默认属于用户私人数据。
- 共建模式必须显式开启，共享内容仅限结构化事件和短摘要。
- 不输出买入、卖出、仓位、止损、目标价、收益概率或自动交易建议。
- 摘要、主题、方向、风险必须能够回溯到原始 ASR 片段和时间戳。
- 任何 P0 验证未通过前，不进入规模化产品开发。

## 阶段 1：容器并发与独立音频验证

### Task 1.1：验证 3 路匿名直播并行播放

**目标:** 证明同一台电脑可匿名并行播放 3 个公开抖音直播间，且互不停止。

**交付物:**
- `demo/reports/demo-01-container-concurrency-report.md`
- 浏览器方案对比表
- 播放稳定性日志

**步骤:**
- [ ] 测试 3 个 Chrome Profile。
- [ ] 测试 3 个独立 Chromium 进程加独立 `user-data-dir`。
- [ ] 测试 Chrome、Safari、Firefox 混合对照组。
- [ ] 每组同时打开 3 个公开直播间，连续运行 2 小时。
- [ ] 记录停流、重载、登录弹窗、页面异常、关闭一路是否影响其他路。
- [ ] 连续 3 个交易日重复关键方案。

**验收标准:**
- 至少一种方案满足 3 路直播连续播放 2 小时。
- 任一路刷新、关闭、异常退出不导致其他直播停止。
- 不要求、不输入、不保存任何抖音账号信息。
- 重复 3 个交易日后，核心方案仍能稳定并行。
- 若没有方案达标，则 No-Go：暂停多直播产品，降级为单直播工具验证。

### Task 1.2：验证每容器独立音频捕获

**目标:** 证明每个直播容器能形成独立音频通道，不串音，不采集其他应用声音。

**交付物:**
- `demo/reports/demo-02-audio-isolation-report.md`
- 音频捕获方案对比表
- 三路音频样本和检查记录

**步骤:**
- [ ] 优先测试页面或标签级音频捕获。
- [ ] 备选测试每进程独立虚拟音频通道。
- [ ] 三路直播分别播放可辨识内容。
- [ ] 同时制造系统提示音和其他应用声音。
- [ ] 分别检查三路输出音频是否只包含对应直播声音。
- [ ] 连续运行 2 小时，记录断流、缺片、静音误判。

**验收标准:**
- 3 路音频无串音。
- 系统提示音、麦克风、其他浏览器或其他应用声音不进入任一路正式音频。
- 每个音频片段可定位到唯一容器、直播会话、序号和起止时间。
- 连续 2 小时无不可恢复断流。
- 若只能录制整机混音，则 No-Go：不进入多直播 ASR 开发。

### Task 1.3：验证后台、最小化和设备状态

**目标:** 确认用户切换窗口、最小化、关闭显示器或锁屏时，直播与音频链路的真实行为。

**交付物:**
- `demo/reports/demo-03-background-state-report.md`
- 支持状态矩阵
- 用户使用限制草案

**步骤:**
- [ ] 测试前台正常播放。
- [ ] 测试窗口最小化。
- [ ] 测试切换到其他应用。
- [ ] 测试切换桌面或虚拟桌面。
- [ ] 测试关闭显示器。
- [ ] 测试锁屏和恢复。
- [ ] 记录每种状态下播放、音频、ASR、恢复策略。

**验收标准:**
- 最小化和切换应用不影响直播和音频捕获。
- 锁屏、休眠、关闭显示器等无法保证的场景有明确产品限制。
- 异常恢复后不会把前后两个直播会话混在一起。
- 需要用户保持设备唤醒时，产品限制被写入 MVP 范围文档。

## 阶段 2：ASR 与单直播理解验证

### Task 2.1：评估股票直播 ASR 方案

**目标:** 选择能实时识别中文股票直播、板块名、数字、否定词和风险词的 ASR 方案。

**交付物:**
- `demo/reports/demo-04-asr-evaluation-report.md`
- ASR 候选方案评分表
- 成本和延迟评估

**步骤:**
- [ ] 选取云端实时 ASR、本地流式 ASR、离线复核模型作为候选。
- [ ] 用阶段 0 测试样本统一评测。
- [ ] 记录字符错误率、主题实体召回率、否定风险召回率、数字准确率、首次延迟、最终延迟、每小时成本。
- [ ] 测试动态热词对板块名、股票口语实体和数字的改善效果。
- [ ] 形成主方案和备用方案。

**验收标准:**
- 主题实体召回率不低于 90%。
- 否定和风险表达召回率不低于 97%。
- 最终句段延迟 P95 不超过 8 秒。
- ASR 临时结果延迟 P95 不超过 3 秒。
- 若风险词和否定词频繁错误，则降级：MVP 只展示原始转写，不生成观点方向。

### Task 2.2：验证语义切分和原意保持

**目标:** 证明系统能从口语直播中提取主题事件，同时不改变否定、条件、风险和不确定性。

**交付物:**
- `demo/reports/demo-05-semantic-integrity-report.md`
- 事件抽取字段定义
- 错误案例集

**步骤:**
- [ ] 使用 500 个标注片段测试短窗口信号发现。
- [ ] 使用中窗口补全条件和风险。
- [ ] 使用长窗口生成阶段摘要。
- [ ] 对每个事件生成主题、方向、理由、条件、周期、风险、证据、置信度。
- [ ] 专项测试“先肯定后否定”“条件成立才关注”“新闻转述”“观点反转”“广告夹杂”。

**验收标准:**
- 方向识别准确率不低于 90%。
- 条件和风险召回率不低于 95%。
- 摘要中不得出现无原文证据的股票、理由、方向或结论。
- 新闻转述不能被标记为主播独立判断。
- 低置信度片段只显示原文或待确认状态，不触发高优先级摘要。

### Task 2.3：验证事件修正、撤回和版本链

**目标:** 确保 ASR 从 partial 到 final 或 corrected 时，下游事件和摘要能同步修正。

**交付物:**
- `demo/reports/demo-06-event-versioning-report.md`
- 事件状态机定义
- 版本链样例

**步骤:**
- [ ] 构造 partial、final、corrected、retracted 四类 ASR 输入。
- [ ] 构造“可以追”修正为“不可以追”的反转样例。
- [ ] 观察单直播事件状态变化。
- [ ] 观察多直播聚合重算。
- [ ] 观察用户提醒是否显示“内容已更新”。

**验收标准:**
- 错误事件可撤回。
- 新旧事件版本可追踪。
- 聚合结果能在规定时间内重算。
- 已触达用户的提醒能显示更新或撤回提示。
- 正式提醒不得只基于 partial 生成；若必须用 partial，只能标为待确认。

## 阶段 3：多直播聚合与个性化规则

**目标:** 证明系统能识别相同主题、保留分歧，并避免把同源新闻重复转述误判成多个独立观点。

**交付物:**
- `demo/reports/demo-07-topic-aggregation-report.md`
- 主题聚合规则说明
- 虚假共识案例集

**步骤:**
- [ ] 使用一个交易日 3 到 5 个主播的标注文本。
- [ ] 人工标记主题、独立观点、同源转述和分歧。
- [ ] 在滑动时间窗口内聚合相似主题。
- [ ] 计算提及直播间数、独立观点数、重复转述数和方向分布。
- [ ] 展示共识、分歧、新出现主题和少数观点。

**验收标准:**
- 主题聚类准确率不低于 85%。

- 虚假共识率不高于 5%。
- 少数观点可见，不能因摘要简洁被删除。
- 每个聚合主题都能回溯到直播间、时间和原始 ASR 证据。

## 阶段 4：MVP 产品闭环实现

### Task 4.1：实现桌面工作台最小闭环

**目标:** 让用户可以添加 3 个公开直播 URL，查看每路状态、实时 ASR、单直播摘要和多直播主题卡片。

**交付物:**
- 可运行 MVP 客户端
- 工作台页面
- 直播详情页
- 主题详情页
- 设置页

**步骤:**
- [ ] 支持用户粘贴公开直播间 URL。
- [ ] 检测 URL 格式和匿名可观看状态。
- [ ] 为每个 URL 创建独立容器。
- [ ] 展示待启动、加载中、播放正常、无音频、需登录、已下播、异常状态。
- [ ] 支持启动、暂停分析、恢复、关闭、重建容器。
- [ ] 展示每路实时 ASR、最近有效信息、摘要和证据片段。
- [ ] 展示多直播主题卡片和详情。

**验收标准:**
- 用户能在同一工作台管理 3 路公开直播。
- 单个容器异常不影响其他容器。
- 无音频、无 ASR、积压、掉线能在 60 秒内提示。
- 需登录直播被标记为不支持，而不是引导用户登录。
- 摘要、AI 生成内容、ASR 原文、用户备注有清晰标识。

### Task 4.2：实现数据分级、权限和删除机制

**目标:** 确保完整 ASR 和私人规则默认私有，结构化共建数据最小化共享，用户可删除历史。

**交付物:**
- 数据分级实现说明
- 权限矩阵测试结果
- 删除流程测试结果

**步骤:**
- [ ] 按 L1 临时原始数据、L2 用户私人数据、L3 结构化共建数据、L4 平台运行数据分级。
- [ ] L1 音频缓冲处理完成后自动删除。
- [ ] L2 完整 ASR、私人笔记、总结规则仅用户本人可见。
- [ ] L3 只有用户显式同意后进入临时共享或聚合。
- [ ] L4 只记录必要运行指标，不记录完整直播文本。
- [ ] 提供用户历史保存期限设置和一键删除。

**验收标准:**
- 私人模式下完整 ASR 不会被其他用户访问。
- 平台运营默认不能直接查看用户完整私人转写。
- 质量测试只能访问授权或脱敏样本。
- 服务端日志不记录完整直播文本和 URL 敏感参数。
- 用户删除私人历史后，系统能在约定期限内完成删除。

### Task 4.3：实现结构化共建和临时计算复用

**目标:** 在用户显式同意时，共享最小结构化事件，并验证同一直播间多用户可复用基础计算。

**交付物:**
- 共建模式流程
- 共享字段白名单
- 复用率和权限隔离测试结果

**步骤:**
- [ ] 共建入口默认关闭。
- [ ] 开启前展示共享范围、权益和退出方式。
- [ ] 共享字段限定为主题、方向、风险条件、发生时间、置信度、必要来源计数。
- [ ] 多个用户同时处理同一直播时，复用一次基础 ASR 或事件提取。
- [ ] 用户退出后停止新增共享事件。
- [ ] 展示用户贡献了哪些结构化信息和获得了哪些额度。

**验收标准:**
- 共建模式必须由用户显式开启，不能默认勾选。
- 完整 ASR、完整音频、连续原文不进入公共共享池。
- 同一共享会话基础 ASR 只运行一次。
- 用户私人 ASR、备注、总结规则不可互访。
- 最后一个活跃用户退出后，共享处理停止。
- 若共享权限或成本复用不达标，则 MVP 关闭跨用户复用，仅保留私人模式。

**验收标准:**
- 音频到达 P95 不超过 2 秒。
- ASR 临时结果 P95 不超过 3 秒。
- ASR 最终句段 P95 不超过 8 秒。
- 单直播信息事件 P95 不超过 20 秒。
- 多直播主题更新 P95 不超过 10 秒。
- UI 更新 P95 不超过 2 秒。
- 3 路运行时设备资源无持续不可接受峰值。
- 若资源不可接受，则降低并发、降低画质、关闭不可见视频渲染或明确最低设备配置。

### Task 5.2：数据重放与模型迭代能力

**目标:** 支持用授权测试数据在不重新采集直播的情况下，对 ASR、提示词、规则和聚合逻辑做回放对比。

**交付物:**
- `demo/reports/demo-11-replay-versioning-report.md`
- 回放数据格式
- 版本对比报告模板

**步骤:**
- [ ] 保存一小时授权测试链路，包括音频引用、ASR 结果、事件、摘要、聚合和版本信息。
- [ ] 使用两个 ASR 或规则版本重新处理同一输入。
- [ ] 对比转写、事件、摘要和聚合差异。
- [ ] 确认新结果不覆盖旧结果。
- [ ] 确认每个输出都能追溯到输入、模型版本、规则版本和处理日志。

**验收标准:**
- 所有输出可追溯到输入和版本。
- 新旧结果可并存和对比。
- 可按直播会话重建结果。
- 事件 ID、版本、输入引用和处理日志齐全。
- 若无法重放和追踪，则暂停模型规模化迭代。

### Task 5.3：五个交易日长期稳定性验证

**目标:** 在真实使用环境下验证连续稳定性、异常恢复和人工维护成本。

**交付物:**
- `demo/reports/demo-12-five-trading-days-stability-report.md`
- 发布风险清单
- Go / No-Go 决策记录

**步骤:**
- [ ] 选择 3 到 5 个公开直播，连续测试 5 个交易日。
- [ ] 覆盖上午和下午主要交易时段。
- [ ] 记录播放可用率、音频可用率、ASR 成功率、端到端延迟、重启次数、人工介入次数、每小时成本。
- [ ] 记录每次异常的触发条件、恢复方式和是否影响其他直播。
- [ ] 汇总成本、资源、准确率和隐私权限风险。

**验收标准:**
- 核心链路可用率不低于 95%。
- 多数异常可自动恢复。
- 每天不需要频繁人工重启。
- 成本可被准确统计到直播间、用户或共享会话维度。
- 单容器异常不级联影响其他容器。
- 若无法达标，则缩小并发、缩小支持范围或重新评估采集容器方案。

### Task 5.4：MVP 发布前合规和产品风险评审

**目标:** 在对外商业化或邀请真实用户前，确认采集方式、共享模式、收费模式和内容输出边界可控。

**交付物:**
- `demo/pre-release-risk-review.md`
- 风险处理清单
- 发布决策记录

**步骤:**
- [ ] 复核产品是否输出交易决策。
- [ ] 复核是否采集或保存账号、Cookie、私密直播、付费直播。
- [ ] 复核是否提供完整公共逐字稿、完整录音回放或主播内容下载。
- [ ] 复核共建字段是否最小化。
- [ ] 复核投诉、纠错、删除入口是否存在。
- [ ] 针对实际采集方式、共享模式和收费模式做专项法律评估。

**验收标准:**
- 产品能力边界不依赖免责声明单独兜底。
- 越界用户请求能被系统阻止。
- 主播、用户和权利人有投诉、纠错、删除渠道。
- 共建模式不暴露完整音频、完整 ASR 或连续原文。
- 合规顾问或负责人明确给出 Go、限量灰度、延期或 No-Go 结论。

## 总体 Go / No-Go 门槛

| 决策点 | Go 条件 | No-Go 或降级 |
| --- | --- | --- |
| 容器并发 | 3 路匿名直播连续 2 小时稳定 | 暂停多直播产品，先做单直播工具 |
| 音频隔离 | 无串音且不采集其他应用声音 | 若只能录系统混音，不进入多直播 ASR 开发 |
| 后台稳定 | 最小化和切换应用不影响链路 | 明确设备唤醒和使用限制 |
| ASR 可用 | 主题实体召回 >= 90%，否定风险召回 >= 97% | 只保留原始转写，不生成观点方向 |
| 语义可靠 | 方向识别 >= 90%，条件风险召回 >= 95% | 取消自动观点方向，只做主题和关键词 |
| 聚合有价值 | 主题聚类 >= 85%，虚假共识率 <= 5% | 只展示相似提及，不宣称共识 |
| 共享可控 | 字段最小化、权限隔离、成本下降 | MVP 维持私人模式，关闭共建复用 |
| 长期稳定 | 5 个交易日核心链路可用率 >= 95% | 缩小并发、支持范围或重新评估容器方案 |
